# Pages, Layouts & Route Params

## What

In the App Router, a `page.tsx` renders a route and a `layout.tsx` wraps it. Both receive
props from the framework. This site's own routes are the worked examples below.

> **Next.js 16 note.** `params` and `searchParams` are **Promises**. In older versions they
> were plain objects. Code written from memory of Next 13 or 14 will not type-check.

## A page: `params` is a Promise

This is the shape of this site's `src/app/docs/[slug]/page.tsx`, with explicit types:

```tsx
import { notFound } from "next/navigation";

type Topic = { slug: string; title: string };

declare function findTopic(slug: string): Topic | undefined;

type Props = {
  params: Promise<{ slug: string }>;
};

export default async function DocPage({ params }: Props) {
  const { slug } = await params;

  const topic = findTopic(slug);
  if (!topic) notFound(); // returns `never`

  return <h1>{topic.title}</h1>; // topic: Topic — narrowed because notFound() never returns
}
```

Three TypeScript ideas in nine lines:

1. **`Promise<{ slug: string }>`** — the route's folder name (`[slug]`) is the property
   name. The type is a claim you make; the framework makes it true.
2. **`async` component** — Server Components may be `async`, and React's types allow a
   component to return `Promise<ReactNode>`.
3. **`notFound(): never`** — control-flow analysis knows nothing follows it, so `topic` is
   narrowed without an assertion (*any, unknown, never, void*).

Forgetting the `await` is a compile error, not a runtime surprise:

```tsx
type Props = { params: Promise<{ slug: string }> };

export default function Page({ params }: Props) {
  const { slug } = params; // Error: Property 'slug' does not exist on type 'Promise<{ slug: string; }>'
  return <h1>{slug}</h1>;
}
```

## `searchParams`

The query string, also a Promise. Values are `string`, `string[]` or missing, so narrow them.

```tsx
type Props = {
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>;
};

export default async function ProductsPage({ searchParams }: Props) {
  const { page } = await searchParams;

  const pageNumber = typeof page === "string" && Number.isInteger(Number(page)) ? Number(page) : 1;

  return <p>Page {pageNumber}</p>;
}
```

`?page=1&page=2` gives `["1", "2"]`, so `page as string` would be a lie; the `typeof` check
is the honest version.

## Generated helpers: `PageProps` and `LayoutProps`

Writing `Props` by hand duplicates information already present in the folder name. Next.js
generates global helper types from your route tree, so you can write the route as a string
and get the params for free. This site uses them in its own pages:

{/* check:skip */}
```tsx title="src/app/docs/[slug]/page.tsx"
export default async function DocPage(props: PageProps<"/docs/[slug]">) {
  const { slug } = await props.params; // slug: string — derived from the route literal
  return <h1>{slug}</h1>;
}
```

{/* check:skip */}
```tsx title="src/app/docs/layout.tsx"
export default function DocsLayout({ children }: LayoutProps<"/docs">) {
  return <div>{children}</div>;
}
```

- They are **global**: no import needed.
- They are generated by `next dev`, `next build` or `next typegen`. That is why a bare
  `tsc --noEmit` fails on a fresh clone with *Cannot find name 'PageProps'*, and why this
  project's `npm run typecheck` runs `next typegen` first.
- A mistyped route literal such as `PageProps<"/docz/[slug]">` is an error, because the
  route does not exist.

(These two blocks are excluded from this site's compile checks for exactly that reason: they
only mean something inside a project that has generated its route types.)

## Dynamic segment shapes

| Folder | Example URL | `params` type |
| ------ | ----------- | ------------- |
| `[slug]` | `/a` | `{ slug: string }` |
| `[...slug]` | `/a/b/c` | `{ slug: string[] }` |
| `[[...slug]]` | `/` or `/a/b` | `{ slug?: string[] }` |
| `[team]/[project]` | `/acme/web` | `{ team: string; project: string }` |

```tsx
type Props = { params: Promise<{ segments: string[] }> }; // app/files/[...segments]/page.tsx

export default async function FilePage({ params }: Props) {
  const { segments } = await params;
  return <p>{segments.join("/")}</p>;
}
```

## Static generation: `generateStaticParams`

Return one object per page to prerender. Its element type must match `params`.

```tsx
type Topic = { slug: string };

declare const publishedTopics: readonly { topic: Topic }[];

export function generateStaticParams(): Array<{ slug: string }> {
  return publishedTopics.map((entry) => ({ slug: entry.topic.slug }));
}

export const dynamicParams = false; // any other slug is a 404
```

This is how all of this site's topic pages are built at `next build`.

## Metadata

`Metadata` is a typed description of `<head>`: titles, descriptions, Open Graph.

```tsx
import type { Metadata } from "next";

type Topic = { slug: string; title: string; summary: string };
declare function findTopic(slug: string): Topic | undefined;

type Props = { params: Promise<{ slug: string }> };

export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const { slug } = await params;
  const topic = findTopic(slug);
  if (!topic) return {};

  return { title: topic.title, description: topic.summary };
}

export const wrong: Metadata = { title: 42 }; // Error: a number is not a valid title
```

Two rules from the docs: `generateMetadata` and the static `metadata` export work only in
Server Components, and you cannot export both from the same segment.

## Layouts

A layout takes `children` and wraps the page. It is not re-rendered on navigation between
its child pages, so state in a layout persists.

```tsx
import type { ReactNode } from "react";

export default function DashboardLayout({ children }: { children: ReactNode }) {
  return (
    <section>
      <nav>Dashboard</nav>
      {children}
    </section>
  );
}
```

Layouts in a dynamic segment also receive `params`; type it the same way, as a Promise.

## Common mistakes

- **Treating `params` as a plain object** (Next 14 habits). Always `await` it.
- **`searchParams.page as string`.** Narrow with `typeof`.
- **Exporting extra things from a `page.tsx`.** Only specific names (`default`,
  `generateMetadata`, `generateStaticParams`, `dynamicParams`, ...) are allowed.
- **Typing `params` as `{ slug: string }`** without the Promise.
- **Forgetting `next typegen`** in CI, then seeing *Cannot find name 'PageProps'*.

## Practice

1. Create `app/shop/[category]/[id]/page.tsx` and type its `params` explicitly, then with
   `PageProps<"/shop/[category]/[id]">`. What does each give you that the other does not?
2. Write a catch-all page `app/docs/[...path]/page.tsx` that rejects an empty path with
   `notFound()`.
3. Write a `generateMetadata` that returns `{}` for unknown slugs. Why is returning
   `{}` safer than throwing here?
