# useRef & useContext

## What

`useRef` gives you a box that survives re-renders without causing them. `useContext`
reads a value from a distant ancestor. Both have a typing trap involving `null`.

## `useRef` for DOM elements

Pass the element type and `null`. The ref is `null` until React attaches the element.

```tsx
import { useRef } from "react";

function SearchBox() {
  const inputRef = useRef<HTMLInputElement>(null); // RefObject<HTMLInputElement | null>

  function focusInput() {
    inputRef.current?.focus(); // current may be null: before mount, or after unmount
  }

  return (
    <>
      <input ref={inputRef} />
      <button onClick={focusInput}>Focus</button>
    </>
  );
}
```

`current` is typed `HTMLInputElement | null`, so the optional chaining is required. It is
not ceremony: the element genuinely does not exist yet during the first render.

The element type tells TypeScript which props `ref` accepts. A mismatch is an error:

```tsx
import { useRef } from "react";

function Wrong() {
  const divRef = useRef<HTMLDivElement>(null);
  return <input ref={divRef} />; // Error: 'RefObject<HTMLDivElement | null>' is not assignable to the input's ref
}
```

Common element types: `HTMLInputElement`, `HTMLButtonElement`, `HTMLFormElement`,
`HTMLDivElement`, `HTMLTextAreaElement`, `HTMLSelectElement`, `HTMLCanvasElement`.

## `useRef` for mutable values

Pass a real initial value, and `current` is writable and not nullable.

```tsx
import { useEffect, useRef, useState } from "react";

function Stopwatch() {
  const [seconds, setSeconds] = useState(0);
  const timerId = useRef<number | undefined>(undefined); // handle for the interval
  const clicks = useRef(0); // a counter that never needs to re-render

  useEffect(() => {
    timerId.current = window.setInterval(() => setSeconds((s) => s + 1), 1000);
    return () => window.clearInterval(timerId.current);
  }, []);

  return (
    <button onClick={() => (clicks.current += 1)}>
      {seconds}s
    </button>
  );
}
```

React 19's `useRef` **requires** an argument: `useRef<number>()` is an error. Use `undefined`
explicitly to say "nothing yet".

## `ref` is a normal prop in React 19

Function components can accept `ref` directly, so `forwardRef` is no longer needed. Using
`ComponentProps` means the ref's type comes for free:

```tsx
import { useRef } from "react";
import type { ComponentProps } from "react";

function TextField({ label, ref, ...rest }: ComponentProps<"input"> & { label: string }) {
  return (
    <label>
      {label}
      <input ref={ref} {...rest} />
    </label>
  );
}

function Form() {
  const emailRef = useRef<HTMLInputElement>(null);
  return <TextField label="Email" ref={emailRef} type="email" />;
}
```

## Context with a guard hook

`createContext` needs a default value. If there is no sensible default, use `null` and
make consumers get a non-null value through a small hook, so no component has to
null-check.

```tsx
import { createContext, useContext, useState } from "react";
import type { ReactNode } from "react";

type Theme = "light" | "dark";

type ThemeContextValue = {
  theme: Theme;
  toggle: () => void;
};

const ThemeContext = createContext<ThemeContextValue | null>(null);

export function ThemeProvider({ children }: { children: ReactNode }) {
  const [theme, setTheme] = useState<Theme>("light");
  const toggle = () => setTheme((current) => (current === "light" ? "dark" : "light"));

  return <ThemeContext value={{ theme, toggle }}>{children}</ThemeContext>;
}

export function useTheme(): ThemeContextValue {
  const context = useContext(ThemeContext);
  if (context === null) {
    throw new Error("useTheme must be used inside <ThemeProvider>");
  }
  return context; // narrowed: ThemeContextValue
}

function ThemeButton() {
  const { theme, toggle } = useTheme(); // no null check needed here
  return <button onClick={toggle}>Theme: {theme}</button>;
}
```

The `null` check happens in exactly one place, and it turns a forgotten provider into a
clear error message instead of a "cannot read properties of null" later.

In React 19 the context object is itself the provider (`<ThemeContext value=...>`); the
older `<ThemeContext.Provider>` still works.

### Why not a fake default?

```tsx
import { createContext } from "react";

type Theme = "light" | "dark";
type ThemeContextValue = { theme: Theme; toggle: () => void };

const Required = createContext<ThemeContextValue>(); // Error: Expected 1 arguments, but got 0

const Fake = createContext<ThemeContextValue>({ theme: "light", toggle: () => {} });
```

A fake default (`Fake`) compiles, but forgetting the provider then silently gives every
component a toggle that does nothing. Prefer `null` plus the guard hook.

## Common mistakes

- **`useRef(null)` for a DOM node without the element type.** `current` becomes `null`
  only, and `.focus()` is an error.
- **Reading or writing `ref.current` during render.** For DOM refs it is `null` on the first
  render, and mutating any ref in render makes the component impure. Use effects and handlers.
- **Using `as HTMLInputElement` on `current`.** Check for `null` instead.
- **Putting changing values in a ref and expecting a re-render.** Refs never re-render.
- **Exposing a context value that is `T | null` to consumers.** Wrap it in a guard hook.
