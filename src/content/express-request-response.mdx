# Request & Response Typing

## What

In Express, a handler receives a `Request` and a `Response`. Both are generic, and the
generics are how you describe what goes in and what comes out:

```text
Request<Params, ResBody, ReqBody, ReqQuery>
Response<ResBody>
```

| Parameter | Describes | Default |
| --------- | --------- | ------- |
| `Params` | `req.params` (route parameters) | `ParamsDictionary` (string values) |
| `ResBody` | what the handler sends back | `any` |
| `ReqBody` | `req.body` | **`any`** |
| `ReqQuery` | `req.query` | `ParsedQs` |

> **Express 5 note.** These examples type-check against `@types/express` 5. In Express 5,
> rejected promises from `async` handlers are forwarded to the error handler for you, and
> `req.body` is `undefined` unless a body-parsing middleware ran.

## Route parameters are inferred from the path

```ts
import express from "express";

const app = express();

app.get("/users/:userId/orders/:orderId", (req, res) => {
  const { userId, orderId } = req.params; // both string — inferred from the path text
  res.json({ userId, orderId });
});

app.get("/users/:userId", (req, res) => {
  console.log(req.params.accountId); // Error: Property 'accountId' does not exist
  res.sendStatus(204);
});
```

Route parameters are always **strings**. Convert them yourself, and handle failure:

```ts
import express from "express";

const app = express();

app.get("/users/:id", (req, res) => {
  const id = Number(req.params.id);
  if (!Number.isInteger(id)) {
    res.status(400).json({ error: "id must be an integer" });
    return;
  }
  res.json({ id });
});
```

## Typing the response body

Give `Response` the body type and `res.json` checks what you send.

```ts
import express from "express";
import type { Request, Response } from "express";

type User = { id: number; name: string; email: string };
type ErrorBody = { error: string };

const users: User[] = [{ id: 1, name: "Ada", email: "ada@example.com" }];

const app = express();

app.get("/users/:id", (req: Request<{ id: string }>, res: Response<User | ErrorBody>) => {
  const user = users.find((candidate) => candidate.id === Number(req.params.id));

  if (!user) {
    res.status(404).json({ error: "User not found" });
    return;
  }

  res.json(user);
  res.json({ id: user.id }); // Error: 'email' and 'name' are missing
});
```

## Typing the request body

`req.body` is `any` by default, which means this compiles:

```ts
import express from "express";

const app = express();
app.use(express.json());

app.post("/users", (req, res) => {
  const name: string = req.body.nmae; // typo — compiles, because body is `any`
  res.json({ name });
});
```

Supply the `ReqBody` type argument to get the checks back:

```ts
import express from "express";
import type { Request, Response } from "express";

type CreateUserBody = { name: string; email: string };
type User = { id: number; name: string; email: string };

const app = express();
app.use(express.json());

app.post(
  "/users",
  (req: Request<Record<string, never>, User, CreateUserBody>, res: Response<User>) => {
    const { name, email } = req.body; // both string
    console.log(req.body.nmae); // Error: Property 'nmae' does not exist
    res.status(201).json({ id: 1, name, email });
  },
);
```

> **This is a claim, not a check.** The `CreateUserBody` annotation tells the compiler what
> to expect. It does not verify what the client actually sent. A client can post `{}` and the
> types will say `name` is a `string`. Runtime validation is covered in [*DTOs & Runtime
> Validation*](/docs/dtos-and-validation) — treat this typing as step one only.

The four-argument `Request<...>` is noisy. A local alias keeps handlers readable:

```ts
import type { Request, Response } from "express";

type Handler<Params = Record<string, never>, Body = unknown, ResBody = unknown, Query = Record<string, never>> = (
  req: Request<Params, ResBody, Body, Query>,
  res: Response<ResBody>,
) => void | Promise<void>;

type User = { id: number; name: string };
type CreateUserBody = { name: string };

const createUser: Handler<Record<string, never>, CreateUserBody, User> = (req, res) => {
  res.status(201).json({ id: 1, name: req.body.name });
};
```

## Query strings

`req.query` values can be `string`, `string[]`, nested objects, or missing. Narrow before
using them.

```ts
import express from "express";

const app = express();

app.get("/products", (req, res) => {
  const search = typeof req.query.search === "string" ? req.query.search : "";
  const page = typeof req.query.page === "string" ? Number(req.query.page) : 1;

  const safePage = Number.isInteger(page) && page > 0 ? page : 1;
  res.json({ search, page: safePage });
});
```

Do not write `req.query.page as string`; a request like `?page=1&page=2` makes it an
array.

## `async` handlers

```ts
import express from "express";
import type { Request, Response } from "express";

type User = { id: number; name: string };
declare function findUser(id: number): Promise<User | undefined>;

const app = express();

app.get("/users/:id", async (req: Request<{ id: string }>, res: Response<User | { error: string }>) => {
  const user = await findUser(Number(req.params.id));
  if (!user) {
    res.status(404).json({ error: "Not found" });
    return;
  }
  res.json(user);
});
```

Handlers are typed to return `unknown`, so returning a promise is accepted. In Express 5 a
rejected promise reaches your error middleware automatically.

## Common mistakes

- **Trusting `req.body`'s type** without validating it.
- **Treating `req.params.id` as a number.** It is a string.
- **Casting `req.query.x as string`.** It can be an array or an object.
- **Sending a body that does not match `ResBody`.** Declare it, so `res.json` is checked.
- **Forgetting that `res.json()` does not stop the function.** Return after responding, or
  you may respond twice.

## Practice

1. Type a `PATCH /users/:id` handler: `Params` with `id`, a body that is
   `Partial<Pick<User, "name" | "email">>`, and a response of `User | { error: string }`.
2. Write `parsePositiveInt(value: unknown): number | undefined` and use it for `?page=`
   and `?pageSize=`.
3. Make a `Handler` alias like the one above generic over its return, and use it for three
   different routes.
